FIXTURE-ONLY FAILURE DRILLS

Test the evidence path before infrastructure spend.

These five local scenarios exercise rejection, review routing, and clean recovery with sanitized metadata. They do not inject faults into a live service, contact an OAuth provider, or use employee, customer, prompt, or tool-output content.

SELECT A FIXTURE SCENARIO

Expected results are declared before execution.

REJECTED

Unknown metadata is not accepted or echoed.

Fixture
A sanitized action with one unreviewed field
Expected result
rejected before policy evaluation
Evidence retained
Record count and a generic contract-rejection reason; no raw field value
Recovery
Correct the record against the published contract and submit a new action

REVIEW REQUIRED

Duplicate IDs and timestamp regressions stay visible.

Fixtures
Duplicate action ID and out-of-order timestamp sequences
Expected result
review_required; neither sequence becomes a success-shaped response
Evidence retained
Action identifiers, session references, content hashes, and the rule that matched
Recovery
Preserve the drill report, fix the sequence in a new record set, then evaluate it independently

REVIEW REQUIRED

A sensitive export is a review signal, not a verdict.

Fixture
Sensitive export metadata with an unapproved scope and unknown destination class
Expected result
review_required with declared policy findings
Not performed
No block, external alert, token capture, network request, or disciplinary action
Contract guard
The drill refuses to run if the published action schema stops rejecting unknown fields

NO REVIEW REQUIRED

A later clean action is evaluated on its own evidence.

Fixture
A valid internal read in a distinct session
Expected result
no_review_required
Preservation rule
Prior rejected and review-required drill evidence is not erased
Fairness rule
Review-required asks for context; it never concludes misconduct or malicious intent
