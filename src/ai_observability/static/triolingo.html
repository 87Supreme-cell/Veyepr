TRIOLINGO / 01

One project. Three ways to explain it.

Triolingo translates Veyepr from the language of a computer, to the language of a teammate, to the language of an interviewer. The goal is not to memorize jargon. It is to show that you understand the choices.

01 Plain English 02 System thinking 03 Code thinking
01 Plain English

“How do I know if my AI model is learning?”

Every time the model practices, it leaves a tiny receipt. The receipt says how wrong it was, how strongly it adjusted itself, how many examples it studied, and which practice run it belongs to.

Veyepr collects those receipts and puts the important numbers on a screen. If the loss is falling, learning is usually moving in the right direction. If it spikes, you have a clue to investigate.

Say this in an interview: “I made the training loop observable by turning each step into a structured event instead of relying on scattered print statements.”
02 System thinking

“Where does the information go?”

TRAINER→CAPTURE→SHAPE→ROUTE→VIEW

The trainer produces the data. A capture buffer gives us a safe place to inspect it. The transform checks that values make sense and puts records into one consistent shape. The route chooses the destination. Prometheus stores the time series; Grafana draws it.

The design choice: Each stage has one job. That makes failures easier to locate and lets a real router, such as Cribl Stream, replace the local teaching version later.
03 Code thinking

“What is the actual contract?”

TrainingTelemetry.from_training_step(
    run_id="demo-run",
    step=42,
    loss=0.183,
    gradient_norm=0.91,
    batch_size=32,
)

This constructor is the border between messy training code and trustworthy telemetry. It accepts regular numbers or PyTorch-like scalar tensors, rejects invalid values, and produces a timestamped record with predictable field names.

Why are there no step labels in Prometheus?

A Prometheus label creates a new time series for every distinct value. A step number changes constantly, so it would create too many series. Veyepr keeps only run_id as a training label and stores the current step as the metric value instead.

Say this in an interview: “I controlled cardinality intentionally. High-detail context belongs in the event stream; stable dimensions belong in metric labels.”

TRIOLINGO / CLOSE

The short version: make the invisible loop visible.

Veyepr is an observability pipeline for model training. It captures structured step events, turns the stable parts into Prometheus metrics, and gives developers a clear view of whether a run is healthy.
